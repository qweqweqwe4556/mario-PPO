# 训练历史

本文记录 v0.2.0 之前的主要实验结论。数值来自当时的独立评估或训练回调，不能直接比较不同奖励参数下的 reward。

## 基线与稳定化

最初导入的 `right` 动作空间 checkpoint 可以续训，但模型长期停留在关卡前半段。后续训练加入 `target_kl`、更小的学习率和独立的确定性/随机评估，降低了 PPO 更新后能力突然退化的频率。

奖励封装随后改为只奖励首次到达的新位置，并对死亡统一扣分。这避免智能体在被敌人推回后重复走同一路段获得进度奖励。

## 跳跃持续时间

固定最短按住跳跃键会降低部分已有能力。更有效的约束是设置 `max_jump_hold=7`：连续请求 A 达到限制后，环境强制插入一个松开 A 的决策周期，使策略可以重新触发跳跃。`models/max_hold7_from_1958/best_deterministic_model.zip` 在完整关卡起点评估到达 `x_pos=2226`，因此被选为 v0.2.0 的完整关卡模型。

## 前沿状态课程

`configs/frontier_x2095.json` 保存了从关卡起点到 `x_pos=2095` 的动作前缀。`FrontierStart` 第一次 reset 时重放该前缀，调用 NES 状态备份，后续 reset 直接从这个位置恢复。

混合课程训练同时使用完整起点和前沿起点环境，目的是学习 `x=2095` 后的台阶/缺口技能并保留前半关能力。最终训练回调的前沿随机评估为：

- 10/10 局越过 `x_pos=2300`
- 平均 `x_pos≈2810`
- 最大 `x_pos=2994`
- `flag_get=0/10`

同一个训练目录的完整起点最佳随机模型在独立 20 局复测中平均 `x_pos≈1221`、最大 `x_pos=1789`，说明局部技能还没有稳定整合回完整策略。这是下一阶段最主要的问题。

## 下一阶段

建议继续使用混合课程，但逐步降低前沿环境占比，并以完整起点的越过率作为主保存指标。若完整策略仍退化，可以改用两阶段方法：先训练前沿专家，再对专家轨迹做行为克隆或蒸馏，最后以较小学习率进行 PPO 微调。
